# tidy · 图片预览工具技术选型与方案文档

> 版本：v0.1（草案）　平台：macOS
>
> **⚠️ 文档地位说明**：本文第 2 节（技术选型）仍然有效；**第 3 节及之后的功能细节已过时**，与《[需求文档](tidy-需求文档-PRD.md)》和《[详细设计](tidy-详细设计.md)》不一致之处（如裁剪交互、命名规则、窗口标题、实例模型），一律以那两份文档为准。本文仅保留选型结论与对比背景。

## 1. 需求概述

一个轻量的本地图片预览工具，核心功能：

1. **右键预览**：在 Finder 中右键图片，可通过"服务/快速操作"或"打开方式"用本工具预览。
2. **快捷键切换**：预览窗口内按快捷键（如 `←` / `→`，或 `Space`），切换到当前目录的上一张/下一张图片。
3. **删除到废纸篓**：点击删除按钮，**无需确认**，直接把当前图片移入系统废纸篓（可恢复）。
4. **修剪（裁剪）**：点击裁剪图标进入裁剪模式，鼠标拖拽框选区域，点击"确定"后**另存为**一张新图片，不覆盖原图。

非目标（首版不做）：编辑（旋转/调色）、批量操作、图库管理、Windows/Linux 支持。

## 2. 技术选型

### 2.1 候选方案对比

| 方案 | 右键集成 | 图片渲染 | 裁剪交互 | 体积/性能 | 结论 |
|---|---|---|---|---|---|
| **A. Swift + SwiftUI/AppKit（原生）** | 原生 NSServices / Finder 扩展，体验最佳 | `NSImage`/`ImageIO`，支持 HEIC 等 Apple 格式 | 自绘 overlay + 事件，完全可控 | 小、快、内存低 | ✅ **推荐** |
| B. Electron + Web 前端 | 需注册为"打开方式"应用，可做 Services | HTML `<canvas>` + Cropper.js 生态成熟 | 网页实现简单 | 体积 100MB+，内存高，启动慢 | 备选（若团队只会前端） |
| C. Tauri + Web 前端 | 类似 B，通过 `tauri-nspanel`/Services 可集成 | WebView 渲染 + Rust `image` crate 处理 | 前端实现 | 体积小（~10MB），比 Electron 好 | 备选 |
| D. Python (PyQt/Tkinter) | 集成麻烦，需打包 | 尚可 | 一般 | 打包臃肿、启动慢 | ❌ 不推荐 |

### 2.2 推荐技术栈（方案 A）

| 模块 | 选型 | 说明 |
|---|---|---|
| 语言 | Swift 5.9+ | |
| UI | SwiftUI + AppKit 混合（`NSViewRepresentable` 包裹图片视图） | 裁剪 overlay 用 AppKit 自绘更精确 |
| 最低系统 | macOS 13+ | 覆盖绝大多数用户 |
| 图片解码 | `ImageIO`（`CGImageSource` → `CGImage`） | 支持 JPEG/PNG/HEIC/WebP/GIF；GIF/动图 WebP 用 `NSImageView` 播放；解码上限 50MP 降采样 |
| 图片写出 | `CGImageDestination`（ImageIO） | 裁剪结果维持原格式（有损格式用质量 1.0）；macOS 13 裁剪 WebP 降级 PNG |
| 废纸篓 | `FileManager.trashItem(at:resultingItemURL:)` | 系统级 API，直接进废纸篓、可恢复，无确认弹窗 |
| 右键集成 | ① Finder Sync 扩展（上下文菜单）或 ② NSServices（快速操作）+ 声明图片 UTI 为"打开方式"应用 | 首版建议 ②（实现简单），后续加 ① |
| 目录图片枚举 | `FileManager.contentsOfDirectory` + 白名单 UTI 过滤（jpeg/png/heic/gif/webp/bmp/tiff，不用 `public.image` 兜底） | 自然排序（`localizedStandardCompare`），跳过隐藏文件，缓存当前索引 |
| 快捷键 | `NSEvent` 本地监听 / SwiftUI `.keyboardShortcut` | 浏览态：`→` 下一张、`←` 上一张、`⌫` 删除、`C` 裁剪；裁剪态：`Enter` 保存、`Esc` 退出、方向键微调选区 |
| 构建 | Xcode + Swift Package Manager | 单 target，无第三方依赖（零依赖更利于维护） |

> 若团队以 Web 技术为主，选 **Tauri 2 + 前端**：Rust 侧用 `trash` crate 删到废纸篓、`image` crate 裁剪写盘；前端用 Cropper.js 做框选。其余交互逻辑相同。

## 3. 功能设计

### 3.1 右键预览

- `Info.plist` 声明 `CFBundleDocumentTypes`（UTI：`public.image`）→ 图片"打开方式"中出现本应用；双击/右键打开即预览。
- 追加 NSServices provider，`NSSendTypes: [NSPasteboard.PasteboardType("public.file-url")]`，接收文件路径后打开窗口。用户可在 系统设置 → 键盘 → 键盘快捷键 → 服务 中启用"快速操作"。
- **单实例单窗口**：再次打开任何图片（无论哪个目录）都在现有窗口内切换目录、重建图集，不新开实例。

### 3.2 目录图片切换

```
打开文件 file → dir = file.deletingLastPathComponent()
images = dir 内所有符合 public.image 的文件（按名称排序）
index = images.firstIndex(of: file)
→ 键：index+1（循环）；← 键：index-1（循环）
```

- 边加载边显示：先渲染缩略级图像（`CGImageSourceCreateThumbnailAtIndex`），完整图异步加载替换，保证大图切换流畅。
- 窗口标题显示 `文件名 (index/total)`。
- 切换时预加载相邻 ±1 张。

### 3.3 删除到废纸篓

```swift
try FileManager.default.trashItem(at: currentURL, resultingItemURL: nil)
```

- 单击删除按钮或按 `Delete`：**立即执行，无任何确认框**（明确的产品决策）。
- 删除后自动跳到下一张图片；若是最后一张则跳上一张；目录空则显示空态。
- 移到废纸篓 ≠ 永久删除，误删可从废纸篓恢复——这是"免确认"的安全性依据。
- 按钮悬停显示 tooltip："移到废纸篓（⌫）"。

### 3.4 裁剪模式

**进入**：点击工具栏裁剪图标或按 `C`。

**交互**：
- 覆盖一层半透明遮罩 overlay（`NSView` 自绘）。
- 在图片上按下拖拽 → 画出矩形选区；选区外遮罩变暗（绘制 4 个暗色矩形或用 `NSScreen` 上的 even-odd 填充）。
- 选区带 8 个手柄，可再次拖拽调整；拖动选区内部可整体移动；按 `Esc` 或再点裁剪图标取消退出。
- 显示实时尺寸提示（如 `1280 × 720`）。
- 选区坐标需从视图坐标换算回图像像素坐标（考虑窗口缩放 fit 模式）。

**确定**（点击 ✓ 或 `Enter`）：
1. 用像素坐标对原图 `CGImage` 做 `cropping(to:)`。
2. 弹出**系统另存面板**（NSSavePanel，默认文件名 `原名_crop.png`），由用户选择保存位置 → 写盘。
3. 完成后退出裁剪模式，可选 toast 提示"已保存"。
4. 不修改原图，只另存新文件。

**输出格式**：维持原图格式、不转格式，原则走无损保存。PNG/TIFF/BMP/无损 WebP 比特级无损写盘；JPEG 受其有损压缩格式限制必然重编码，用质量 1.0 最高质量（损失肉眼不可辨），压缩域比特级无损裁剪（jpegtran 类）列为后续增强；HEIC 系统最高质量重编码。

## 5. 工程结构（Swift 版）

应用名称 **tidy**，Bundle ID 建议 `com.nanakon.tidy`；"打开方式"菜单与 Services 菜单中显示为 tidy。

```
tidy/
├── App/                 # 入口、窗口管理、Services 接收
├── Viewer/              # 图片视图、目录枚举、切换逻辑
├── Crop/                # 裁剪 overlay、坐标换算、导出
├── FileOps/             # trashItem 封装、另存
└── Resources/           # Info.plist、图标
```

## 7. 风险与备注

- **免确认删除**：因走废纸篓可恢复，风险可接受；若未来加"永久删除"则必须二次确认。
- **HEIC/动态图**：HEIC 依赖 macOS 系统编解码器（13+ 原生支持）；GIF/WebP 动图首版只播第一帧或直接用 NSImageView 播放 GIF。
- **Finder 右键菜单**：原生"自定义右键菜单项"需要 Finder Sync 扩展，成本较高，故 M5 先用"打开方式 + 快速操作"，两者对用户均满足"右键预览"。
- **超大图**：超过 100MP 的图用缩略级渲染避免卡顿。
