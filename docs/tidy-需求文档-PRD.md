# tidy · 需求文档（PRD）

> 版本：v1.0　平台：macOS 13+　状态：已定稿（随评审意见滚动更新）
> 关联文档：[技术选型与方案](图片预览工具-技术方案.md)、[详细设计](tidy-详细设计.md)

## 1. 背景与目标

### 1.1 问题背景（为什么要做 tidy）

macOS 现有的图片查看方式在"筛选整理图片"这个高频场景下都存在明显断点：

| 现状 | 痛点 |
|---|---|
| Finder 缩略图 | 只能看个大概，**缩略图看不清图片内容**，无法判断一张图该留还是该删 |
| Finder + 预览（Quick Look / 预览.app） | 空格预览能看清内容，但**预览状态下没有删除操作**——想删就得关掉预览、回到 Finder 选中文件、再 ⌘Delete，看一张删一张要来回切换 |
| 整理大批图片的实际流程 | "看内容 → 确认不要 → 删除" 这个动作被拆散在 Finder 和预览之间反复横跳，**内容确认和删除的过程非常麻烦** |
| 需要局部图时 | Mac 预览的裁剪藏在"工具 → 调整大小/裁剪"菜单里，交互繁琐且会改动原文件，**预览本身也没有好用的裁剪功能** |

一句话：**macOS 缺一个把"看清内容"和"顺手删掉/裁出局部"合并成同一处连续动作的工具。**

### 1.2 产品定位

tidy 定位为**极简、快启、顺手**的本地图片预览整理工具：打开即看清内容（全尺寸预览），同一界面内键盘直达删除，两步完成裁剪另存——把"确认 → 删除 → 裁剪"收敛在一个窗口、不离开键盘。

**目标**

- 双击/右键图片即可用 tidy 打开，即点即看，体验以"快"为先（不做硬性时间指标，以实际体验衡量）。
- 不离开键盘即可浏览整个目录的图片并删除废图。
- 看到想裁的图，两步操作（拖拽选框 → 确认另存）得到结果。
- 不做后台服务、不写数据库、不联网。

**非目标（本期不做）**

- 图片编辑（旋转、调色、标注、EXIF 修改）
- 批量删除 / 批量裁剪
- 缩略图墙、图库管理
- Windows / Linux 版本
- 永久删除（只进废纸篓）

### 2. 用户与场景

核心场景围绕 1.1 的痛点展开：

| 用户 | 场景 |
|---|---|
| 摄影师 / 设计师 | 导出一批素材，Finder 里缩略图看不清内容 → 用 tidy 打开目录，全屏翻看，废片直接 `⌫` 进废纸篓，全程不碰 Finder |
| 普通用户 | 下载了一堆图，逐张看、顺手删、顺手裁头像——同一窗口内完成，不用在预览和 Finder 间来回跳 |
| 开发者 | 截图后快速裁出局部区域另存（弥补预览没有好用的裁剪） |

## 3. 功能需求

### FR-1 打开与预览

| 项 | 说明 |
|---|---|
| 描述 | 通过 Finder"打开方式"、双击（设为默认时）、Services 快速操作打开图片 |
| 支持格式 | 白名单：JPEG、PNG、HEIC、GIF（含动图）、WebP、TIFF、BMP。**不用 `public.image` 兜底**（会把 RAW、SVG 等带进来），枚举与打开均按此白名单 UTI 过滤 |
| 显示 | 两种视图模式：**完整预览**（fit 且不超 100%，小图不放大；图片居中，**无滚动条**）/ **占满宽度**（图片宽度铺满窗口，高度超出部分竖向滚动）。默认完整预览；**巨高图（高/宽 ≥ 3，长截图）默认占满宽度**（巨宽图不做特殊优化）。`W` 键或标题栏按钮切换，两模式互不带入滚动状态（窗口规则见 FR-5） |
| 实例模型 | **始终单实例单窗口**。再次打开任何图片（无论是否同一目录）都在现有窗口中**切换目录**：重建图集并定位到被打开的那张，不新开实例、不开新窗口 |
| 裁剪中被打开 | 若正处于裁剪模式，新的打开事件直接**放弃裁剪（丢弃选区）并切换目录**，不弹确认框（选区未保存无数据损失，与"删除不确认"同一效率原则） |
| 目录指示 | 窗口标题统一为 `目录名 — 文件名 (3/24)`（全文唯一格式）；切换目录即整体替换图集（浏览态无未保存内容，直接切换零成本） |
| 多张打开 | 一次打开多张图片时，以**第一张文件所在目录**构建图集并定位到第一张；其余文件若属同一目录自然在图集中，属不同目录则忽略（后续可手动切换） |
| 异常 | **损坏/不支持**：当前项显示错误占位页、**可继续 ←/→ 离开**（不支持格式的文件仍枚举其所在目录的白名单图片作为图集，只是它本身不可预览）；**文件已消失**：不占位、直接从图集移除并跳到下一张。目录中全部文件失效时进入空态页 |

**验收**：右键任一图片 → 打开方式 → tidy，图片直接完整显示、无多余中间页；打开损坏文件不闪退。

### FR-2 目录图片切换

| 项 | 说明 |
|---|---|
| 描述 | 打开后自动枚举所在目录的全部图片作为图集 |
| 快捷键 | `→`：下一张；`←`：上一张；首尾循环。**不提供 Space**（长键程费力，方向键足够） |
| 排序 | 文件名自然排序（photo2.jpg 在 photo10.jpg 之前） |
| 指示 | 窗口标题 `目录名 — 文件名 (3/24)`（与 FR-1 同一格式） |
| 目录变化 | 切换时懒校验：文件已被外部删除 → **从图集移除**并继续找下一张有效文件；全部失效 → 空态页 |
| 性能 | 首帧显示快速缩略图，高清图异步替换；预加载相邻 ±1 张 |

**验收**：100 张图的目录中连续按 `→` 切换流畅、无可感知卡顿。

### FR-3 删除到废纸篓

| 项 | 说明 |
|---|---|
| 描述 | 点击标题栏删除按钮或按 `⌫`，**立即**将当前图片移入系统废纸篓 |
| 确认 | **无任何确认弹窗**（产品决策：废纸篓可恢复，优先操作效率） |
| 后续 | 自动跳到下一张；若删的是最后一张则跳上一张；目录空了显示空态页 |
| 反馈 | 删除成功：toast「已移到废纸篓：xxx.jpg」（带文件名），3s 自动消失 |
| 边界 | 失败分两种：**文件已不存在**（被外部删掉）→ 从图集移除并跳到下一张，toast「文件已不存在：xxx.jpg」；**占用/权限失败**（文件还在磁盘上）→ **停留在当前张**，toast 报错带文件名。绝不把"还在盘上"的文件从图集里悄悄拿掉，避免用户误以为已删除 |

**验收**：点删除后图片立即从目录消失且出现在废纸篓；全程无弹窗。

### FR-4 裁剪（修剪）

| 项 | 说明 |
|---|---|
| 进入 | 点击标题栏裁剪图标，或按 `C` |
| 初始选框 | 进入裁剪模式后，图片上**直接出现一个默认选框**（覆盖图片 **100%** 全部区域），用户**拖拽线框**（8 个手柄调整、拖框内整体移动）来缩小/移动到目标区域；默认全选意味着"大多数时候只需往里拖一两下"，避免从 60% 再往外扩的额外操作 |
| 视觉 | 选区外遮罩变暗；选区白边 + 三分线；右下角显示实时像素尺寸 `1280 × 720`。**可拖拽区域有悬停反馈**：悬停手柄时光标变化（角→十字、边→双向箭头）且手柄高亮放大，悬停选区内部变小手（拖动中变握拳） |
| 自适应 | **缩放/窗口尺寸变化时选区按比例映射**：保持相对图片的位置与比例（100% 全选仍全选），不漂移、不失效；图片放大出现滚动条时选区跟随图片滚动，滚动/缩放状态下均可正常拖拽与保存 |
| 保存 | 点击标题栏保存按钮（或 `Enter`）→ **直接保存**新文件到原图同目录（**不弹另存面板**、不让用户选位置，文件名按命名规则自动取、跳过已存在），原图不动 → **自动退出裁剪模式**回到浏览态；写盘失败留在裁剪模式并 toast 报错（选区保留）。选区未调整（仍是 100% 全选）时按保存**允许执行**（保存整图副本是合法用途；原图不动、新文件可删，与"删除不确认"同一效率原则） |
| 保存后 | 新文件**插入当前图集**（位于原图之后，命名规则保证排序相邻），仅 toast 提示，不自动跳转 |
| 取消 | `Esc` 或再点裁剪图标退出裁剪模式，选区丢弃 |
| 命名 | 保存文件名 = 当前图片名追加序号：`photo_001.jpg` → `photo_001 (2).jpg`、再裁再存 `photo_001 (3).jpg`……序号自动跳过已存在的文件名；同目录排序上与原图紧挨 |
| 输出 | **维持原图格式，不转格式**（例外：macOS 13 无 WebP 编码器，裁剪 WebP 降级输出 PNG 并 toast 说明）。PNG/TIFF/BMP 为比特级无损写盘；JPEG 受格式限制必然重编码，采用质量 1.0（最高质量，损失肉眼不可辨）；HEIC、有损 WebP 用系统最高质量重编码（视觉无损、非比特级）。保留方向信息（EXIF orientation） |
| 无损说明 | "无损"的准确表述：PNG/TIFF/BMP 为比特级无损；JPEG/HEIC/有损 WebP 为最高质量重编码（受其有损压缩格式本身限制）。JPEG 压缩域比特级无损裁剪（jpegtran 类方案）列为 v0.2 增强，不阻塞本期 |
| 范围 | **不可裁剪的情形一律裁剪按钮置灰 + `C` 无效**：动图（GIF/动图 WebP，toast「动图暂不支持裁剪」）、白名单外格式（RAW/SVG，本身显示错误占位页）、解码失败（错误占位页）、图像尚未加载完成；就绪且非动图才可进入 |
| 边界 | 选区下限统一为 **10×10 pt**（视图坐标），拖拽中被 clamp、低于下限视为误触；拖出图片边界自动 clamp。手柄热区**只向选区内侧认**（外扩 3pt 容差）：100% 全选时手柄贴着窗口边缘，外侧点击留给窗口缩放，避免拖手柄与拖窗口互相误触 |

**验收**：进入裁剪模式即见默认选框，拖拽线框调整区域，点保存后同目录出现 `原名 (2)` 新文件且已退出裁剪模式；GIF 图片上无法进入裁剪；原图未被修改。

### FR-5 窗口与通用交互

- 快捷键总表（浏览态）：`→` 下一张、`←` 上一张、`⌫` 删除、`C` 进入裁剪、`W` 切换视图（完整预览 ⇄ 占满宽度）、`⌘C` 复制划选文本、`Esc` 清除文本划选。**不提供 Space** 切换。
- 快捷键总表（裁剪态）：`Enter` 保存另存、`Esc` 取消退出、方向键微调选区 1pt（Shift+方向 10pt）、`W` 切换视图（选区随缩放等比映射）；**裁剪态下其余快捷键（含 `⌫` 删除、`C`）一律不响应**。
- 视图模式规则：两种视图都跟随窗口尺寸（完整预览重排、占满宽度始终铺满宽度）；占满宽度放大上限 8 倍；切换图片重置为该图的默认视图并滚回文档起点（长截图从顶部开始）。
- 图片区深色背景；**标题栏/工具栏的背景与图标颜色跟随系统外观**（与 Mac 预览一致）；窗口尺寸变化时图片 fit 重排。
- 操作按钮（浏览态：复制全部文本、视图切换、删除、裁剪；裁剪态：保存、退出）置于**窗口标题栏右侧**，与全屏按钮同一区域（参考 Mac 预览），**不单设工具栏区域**；**不提供"上一张/下一张"按钮**，切换仅键盘快捷键。
- **窗口固定 1:1 正方形**：初始边长 = min(屏幕可用宽 −36pt, 可用高 −87pt)（近满高），在可用区内居中；**比例锁定**——拖拽调整窗口始终为正方形，内容最小 480×480；打开与切换图片均不改变窗口大小，**不记忆、不还原用户调整**。
- 空态页：目录无图片（或全部失效）时提示，按钮"打开其他文件夹"唤起系统 **NSOpenPanel** 选目录（无沙盒，选择即获得该目录访问同意），选中后切换图集。

### FR-6 文本识别（划选复制）

| 项 | 说明 |
|---|---|
| 识别 | 浏览静态图片时**自动后台识别**图中文字（系统 Vision OCR，中英文），不打断浏览；识别完成后即可划选 |
| 划选 | 鼠标在图片文字上按下拖动即**划选文本（字符级，与 Mac 预览一致）**，选中部分高亮；悬停文本行时光标变 I 型；点击行外区域或 `Esc` 清除划选 |
| 复制 | `⌘C` 复制划选文本（行间换行拼接）；标题栏「复制全部文本」按钮一键复制全图识别文本；复制成功 toast 提示 |
| 范围 | **仅静态图片**：动图（GIF/动图 WebP）、白名单外格式、解码失败（错误占位页）不识别；识别失败或无文字时按钮置灰、划选不可用，不影响其他功能 |
| 兼容 | 裁剪态下划选关闭（裁剪手柄优先）；缩放/滚动/视图模式切换不影响行框位置（行框随图片走） |

**验收**：打开含文字的截图，鼠标拖过文字出现高亮，`⌘C` 后剪贴板得到对应文字；点「复制全部文本」得到全图文字；GIF 上按钮置灰、无法划选。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 无硬性耗时与内存指标，以体验为先：缩略图先显示、高清图异步替换、大图降采样渲染（>50MP 上限），缓存总量有界 |
| 可靠性 | 任何单文件损坏不影响其他图片浏览；删除失败不丢数据 |
| 隐私安全 | 完全本地运行，无网络请求；**不开 App Sandbox**（非 App Store 分发，无上架要求），仅开 Hardened Runtime 满足公证 |
| 兼容 | macOS 13 Ventura 及以上，Apple Silicon 与 Intel。注：WebP 编码（裁剪保存回 WebP）系统支持自 macOS 14 起；macOS 13 上裁剪 WebP 降级输出 PNG 并 toast 说明 |
| 分发 | Developer ID 签名 + 公证，支持直接分发 dmg |
